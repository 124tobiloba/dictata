<objective>
Deliver the destructive half of data ownership end-to-end: delete one dictation from a hidden dashboard affordance, clear all history after a count-naming confirmation, and make every surface agree that the row is gone.

Purpose: DATA-01/02/03 are the core promise of the product — deleted means deleted everywhere, immediately and after a restart. This plan also removes the stats drift at its source by making `stats` a derived value.

Output: one mutation path (`purgeEntry` / `clearAll` in the main process) shared by the dashboard routes and the History-window IPC, a flushed store, a purged event bus, recomputed stats, and a re-derived paste-last target.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dashboard browser page → local HTTP server | Untrusted request target, method, query token and id cross here |
| renderer windows → main process IPC | A sandboxed renderer asks the main process to destroy data |
| main process memory → disk | Debounced writes and in-memory buffers decide whether "deleted" survives |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Information disclosure | `Store._save()` 150 ms debounce + `before-quit` | high | mitigate | Destructive mutations call `flush()` synchronously; `before-quit` flushes first, so a delete followed by an immediate quit cannot resurrect the row. |
| T-01-02 | Information disclosure | `EventBus.buffer` feeding `/api/state` and SSE | high | mitigate | `bus.forgetMany(ids)` inside the single mutation path removes the dictation and its error events before the next snapshot or replay; clear-all uses `forgetAll()`. |
| T-01-03 | Information disclosure | `lastCleaned` driving the paste-last hotkey | high | mitigate | `rederiveLast()` runs after every delete/clear and at startup; `paste-last` falls back to the surviving history, never to a deleted string. |
| T-01-04 | Elevation of privilege / Spoofing | `DELETE /api/history/:id` and `DELETE /api/history` | high | mitigate | Host allowlist stays first, token checked before any mutation, id validated against the UUID pattern before it reaches Map/filter, foreign `Origin` rejected on non-GET, method + path matched before the static fallthrough. |
| T-01-05 | Tampering | `src/renderer/historyRenderer.js` removing its own DOM node | low | mitigate | The local removal is deleted; the History window re-renders only from the authoritative `vf:history-updated` snapshot produced by the same mutation path as the dashboard. |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package changes in this phase; `npm install` must not run. Any future dependency requires the package-legitimacy gate and a blocking human checkpoint. |
</threat_model>
